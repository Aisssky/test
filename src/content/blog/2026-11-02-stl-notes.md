## 0. 先立框架

### 0.1 标准库以头文件方式呈现

| 情况 | 写法 | 说明 |
| --- | --- | --- |
| 新式 C++ 头文件 | `#include <vector>` | **不带副档名（.h）** |
| 新式 C 头文件 | `#include <cstdio>` | 不带 .h，但加 `c` 前缀 |
| 旧式 C 头文件 | `#include <stdio.h>` | 仍然可用，兼容用 |

新式头文件内的组件**封装于 `namespace std`**：

```cpp
using namespace std;   // 全量引入（省事，但有污染风险）
using std::cout;       // 单个引入（推荐写法）
```

> **补充 · 实践建议**：`using namespace std;` 别写在头文件里，否则会把整个 std 灌进所有包含它的翻译单元，容易和用户代码的 `count`、`distance`、`data` 等名字撞车。源文件里图省事可以用，头文件里一律写全名或 `using std::xxx;`。

### 0.2 STL 六大部件

STL（Standard Template Library）是 C++ 标准库的一个子集，由六大部件协作组成：

| 部件 | 英文 | 干什么 | 典型代表 |
| --- | --- | --- | --- |
| 容器 | Containers | 存数据 | `vector` / `list` / `map` |
| 分配器 | Allocators | 管内存（容器向它要空间） | `allocator<int>` |
| 算法 | Algorithms | 处理数据 | `sort` / `count_if` |
| 迭代器 | Iterators | 算法与容器之间的桥 | `begin()` / `end()` |
| 适配器 | Adapters | 改造容器 / 迭代器 / 仿函式 | `stack` / `reverse_iterator` / `bind2nd` |
| 仿函式 | Functors | 给算法传“策略” | `less<int>` / 自定义 `cmp` |

协作关系（一张图记住）：

```
                 ┌──────────── 算法 Algorithms ────────────┐
                 │   sort / count_if / find / copy ...     │
                 └───────────────┬─────────────────────────┘
                                 │ 只认迭代器，不认容器
                    ┌────────────▼────────────┐
                    │   迭代器 Iterators      │
                    └────────────┬────────────┘
                                 │ 由容器提供
                 ┌───────────────▼─────────────────────────┐
                 │   容器 Containers                       │
                 │   vector / list / map / set ...         │
                 └───────────────┬─────────────────────────┘
                                 │ 向分配器要内存
                    ┌────────────▼────────────┐
                    │  分配器 Allocators      │
                    └─────────────────────────┘

        仿函式 Functors ──作为参数喂给算法（决定“怎么比”）
        适配器 Adapters ──改造上面任意一个（stack 改造容器、
                          bind2nd 改造仿函式、反向迭代器改造迭代器）
```

**关键理解**：算法不知道容器的存在，它只接收一对迭代器 + 一个可选的“策略”（仿函式）。这就是 STL 能把 `M` 个算法和 `N` 个容器组合出 `M×N` 种用法的原因。

### 0.3 一段程序看全六大部件

```cpp
#include <vector>
#include <algorithm>
#include <functional>
#include <iostream>
using namespace std;

int main()
{
    int ia[6] = { 27, 210, 12, 47, 109, 83 };
    vector<int, allocator<int>> vi(ia, ia + 6);
    cout << count_if(vi.begin(), vi.end(), not1(bind2nd(less<int>(), 40)));
    return 0;
}
```

逐句拆解（这段就是六大部件的全家福）：

| 代码片段 | 对应部件 |
| --- | --- |
| `vector<int, allocator<int>>` | **容器** + **分配器**（第二模板参数就是分配器，不写默认也是 `allocator<int>`） |
| `ia, ia + 6` | 用一段原生数组的**迭代器区间**构造容器 |
| `vi.begin(), vi.end()` | **迭代器** |
| `count_if(...)` | **算法**（数满足条件的元素个数） |
| `less<int>()` | **仿函式**（判断 x < y） |
| `bind2nd(..., 40)`、`not1(...)` | **适配器**（把二元仿函式绑定第二个参数 → 变成一元；再取反） |

**输出结果是 `4`**。推导：`less<int>()(x, 40)` 即 `x < 40`；`bind2nd` 把 40 绑到第二参数，仍是 `x < 40`；`not1` 取反 → `x >= 40`。数组中 ≥ 40 的是 `210、47、109、83`，共 4 个。

> **补充 · 这段代码在今天是过时的**：`bind2nd`、`not1`、`ptr_fun` 等“函数绑定器”在 C++11 标记废弃，**C++17 已从标准中移除**。现代等价写法：
>
> ```cpp
> cout << count_if(vi.begin(), vi.end(), [](int x) { return x >= 40; });
> ```
>
> 或者用 `std::bind` / `std::not_fn`。原写法在旧编译器（如 VC6、老版 GCC）上还能跑，新标准下会直接编译失败——这是读老课件最容易踩的一个坑。

### 0.4 复杂度：先建立量级直觉

| 记号 | 名称 | 直观含义 | STL 里的典型例子 |
| --- | --- | --- | --- |
| O(1) / O(c) | 常数时间 constant time | 和数据量无关 | `vector[i]`、`push_back`（均摊）、`stack::top` |
| O(log₂n) | 次线性时间 sub-linear time | 每步砍一半 | `map::find`、`lower_bound`、堆的 `push` |
| O(n) | 线性时间 linear time | 数据翻倍时间翻倍 | `vector::clear`、`find`、遍历 |
| O(nlog₂n) | 线性与二次之间的中间形态 | 排序的标杆 | `sort`、`stable_sort`、`list::sort` |
| O(n²) | 平方时间 quadratic time | 双重循环 | 朴素冒泡/插入排序 |
| O(n³) | 立方时间 cubic time | 三重循环 | 朴素矩阵乘法 |
| O(2ⁿ) | 指数时间 exponential time | 每加一个元素翻倍 | 朴素斐波那契、枚举子集 |

几个必须分清的点（补充）：

- **均摊（amortized）O(1)**：`vector::push_back` 偶尔会触发扩容，单次是 O(n)，但摊到每次插入上是 O(1)。「均摊」≠「每次」。
- **O(logn) 的常数因子不小**：红黑树查找要沿树走十几层、每次比指针跳转，比 `vector` 里连续内存的二分慢得多。所以小数据量下 `vector + lower_bound` 常常赢过 `set`。
- **最坏 vs 平均**：`unordered_*` 平均 O(1)，但哈希冲突严重时最坏退化到 O(n)（全部落进同一个桶）。
- **对数底数不影响量级**：O(log₂n) 与 O(log₁₀n) 只差常数倍，Big-O 里统一写 O(logn)。

### 0.5 C++11 带来的两个日常写法

#### auto：自动类型推断

- 引入 `auto` 关键字，编译器**根据变量初始化表达式**推断类型，代码更灵活、更可读。
- 常配合迭代器用，省掉一长串类型名：

```cpp
// C++98 写法
vector<int>::iterator it = v.begin();
// C++11 写法
auto it = v.begin();

for (auto x : v) { ... }        // 拷贝一份（修改不影响原容器）
for (auto& x : v) { x *= 2; }   // 引用（能改到原元素）
for (const auto& x : v) { ... } // 只读，且不拷贝（遍历大对象首选）
```

#### auto 类型推导的原理

> 原文：编译器根据初始值来推算变量的类型，**要求用 auto 定义变量时必须有初始值**。编译器推断出来的 auto 类型有时和初始值类型并不完全一样，编译器会适当改变结果类型使其更符合初始化规则。

补充几条实际会撞上的规则：

| 写法 | 实际类型 | 说明 |
| --- | --- | --- |
| `const int ci = 0; auto x = ci;` | `int` | **顶层 const 被丢弃** |
| `int i = 0; int& r = i; auto x = r;` | `int` | **引用被丢弃**（要引用得写 `auto&`） |
| `const int& cr = i; auto& x = cr;` | `const int&` | 用 `auto&` 时才保留 const |
| `int a[3]; auto p = a;` | `int*` | **数组退化为指针**（要保留数组类型用 `auto&` 或 `decltype(a)`） |
| `auto x = {1, 2, 3};` | `std::initializer_list<int>` | 花括号初始化有特殊规则 |

一句话记法：**`auto` 会剥掉引用和顶层 const，要保留就自己写 `auto&` / `const auto&`**。想知道“原样类型”，用 `decltype`。

> **补充 · 同一批里最常用的还有**：`nullptr`（替代 `NULL`）、移动语义与右值引用 `&&`、`std::unique_ptr/shared_ptr`、统一初始化 `{}`、`override/final`、`lambda`（见 0.3 的现代写法）。这些和 STL 配合最多，建议一并过一遍。

## 1. 容器

### 1.1 分类总览

C++ STL 的容器分三大类，**分类决定接口，接口决定你该选谁**：

```
容器
├── 序列式容器（sequence）—— 元素按插入位置排，关心“顺序”
│   ├── array           固定大小
│   ├── vector          动态数组（默认首选）
│   ├── deque           双端队列
│   ├── list            双向链表
│   └── forward_list    单向链表
│
├── 关联式容器（associative）—— 元素按 key 自动排序/散列，关心“查找”
│   ├── 有序（红黑树）
│   │   ├── set / multiset          key = value
│   │   └── map / multimap          key → value
│   └── 无序（哈希表）
│       ├── unordered_set / unordered_multiset
│       └── unordered_map / unordered_multimap
│
└── 容器适配器（adapter）—— 不自己存数据，套在别的容器上换接口
    ├── stack            后进先出
    ├── queue            先进先出
    └── priority_queue   每次取最值
```

#### 序列式容器对照表

| 容器 | 特点 | 常见操作复杂度 / 注意 |
| --- | --- | --- |
| `std::array` | 固定大小数组，不能插入/删除 | 随机访问 O(1)；大小编译期确定 |
| `std::vector` | 动态数组，尾插高效 | 尾插均摊 O(1)，中间插入/删除 O(n)；**不是先进后出** |
| `std::deque` | 双端队列，头尾插入删除高效 | 头尾 O(1)，中间 O(n)；**分段连续存储** |
| `std::list` | 双向链表 | 任意位置插入/删除 O(1)，但查找 O(n) |
| `std::forward_list` | 单向链表 | 只能单向遍历，节省空间 |

> 对照表里的「不是先进后出」是原笔记的提醒：`vector` 提供了 `push_back/pop_back`，用起来像栈，但它依然允许随机访问和中间插删，**语义上不是栈**。要栈的语义就用 `stack`（见 1.6）。

#### 关联式容器

**有序关联**（主流实现为红黑树）：

- `set` / `multiset`：**key = value**，只存键，值就是键本身。
- `map` / `multimap`：存 **key → value** 对。
- `set` 和 `map` 的底层都是**红黑树**，但标准库并没有规定必须这样（只是主流实现如此）。
- `multi` 版本允许重复元素存在。
- 共同点：自动按 key 有序、查找/插入/删除都是 O(logn)、不支持随机访问（没有 `[]` 下标语义，`map` 的 `[]` 是按键取值）、迭代器是双向的。

**无序关联**（主流实现为哈希表）：

- `unordered_map` / `unordered_multimap`、`unordered_set` / `unordered_multiset`。
- 底层是哈希表 HashTable，**原名都叫 `hash_map` / `hash_set`**（非标准扩展，如 SGI STL、旧版 MSVC）。
- 常见底层是哈希表，但标准没有规定具体实现。
- 平均查找 O(1)，**最坏 O(n)**。
- 历史实现中曾有 `hash_map/hash_set`，但**标准名是 `unordered_*`**。
- 不支持自动排序，遍历顺序不确定。

#### 容器适配器

| 适配器 | 语义 | 默认底层容器 | 说明 |
| --- | --- | --- | --- |
| `stack` | 后进先出 LIFO | `deque` | 只暴露 `push/pop/top/empty/size` |
| `queue` | 先进先出 FIFO | `deque` | 只暴露 `push/pop/front/back/empty/size` |
| `priority_queue` | 每次取最值（堆） | `vector` | 只暴露 `push/pop/top/empty/size` |

注意：

- **`stack` 不是容器，而是容器适配器。**
- **适配器不提供迭代器**，只暴露有限接口——所以不能对 `stack` 做 `for` 遍历，也不能传给 `sort`。
- 适配器可以换底层：`stack<int, vector<int>>`、`queue<int, list<int>>` 都合法（换的容器得支持所需操作）。

> **补充 · 三者的底层**：`stack`/`queue` 只是把底层容器的接口“掐头去尾”露出来；`priority_queue` 靠 `make_heap / push_heap / pop_heap` 这组堆算法维护 `vector` 里的完全二叉树结构，所以 `top()` 是 O(1)、`push/pop` 是 O(logn)，而它的迭代器？没有——堆的内部数组顺序不是有序的，暴露迭代器会误导人。

### 1.2 vector

变长数组。头文件：`#include <vector>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| push_back() | 在最后插入一个元素 | O(1) |
| pop_back() | 在最后删除一个元素 | O(1) |
| [i] | 随机访问 | O(1) |
| size() | 查询容器大小 | O(1) |
| clear() | 清空 | O(n) |
| empty() | 判断是否为空 | O(1) |
| insert() | 插入 | O(n) |
| erase() | 删除 | O(n) |

#### 示例

```cpp
vector<int> v;                 // 初始长度为 0 的 vector
v.push_back(1); v.push_back(114); v.push_back(114514); v.pop_back();

for (int i = 0; i < v.size(); i++) {
    cout << v[i] << " ";
}

if (!v.empty()) {
    // ...
}

v.insert(it, 5);               // 在迭代器 it 前插入
it = v.erase(it);              // 删除 it 指向的元素，返回下一个位置
it = v.erase(it, v.end());     // 删除区间 [it, end)

vector<int> v1(n);             // 初始长度为 n，默认以 0 填充
vector<int> v1(n, k);          // 初始长度为 n，以 k 填充
```

> **补充 · 底层与扩容**：`vector` 是一块**连续内存** + `size`（已有元素）+ `capacity`（已申请容量）。`push_back` 发现容量不够时，会申请一块更大的内存（通常是 1.5× 或 2×，由实现决定）、把老元素**搬过去**、再释放旧内存。
>
> 后果有两个：① 扩容是 O(n)，所以“均摊 O(1)”成立；② **扩容会让所有迭代器、指针、引用失效**。知道容量时先 `v.reserve(n)` 可以避免反复扩容。

#### 迭代器

1. 可以简单理解为指针或地址，或更简单的理解为位置，针对不同容器有不同的迭代器实现
2. 可以用来遍历容器，通过 `*` 来解引用访问内部元素
3. 注意迭代器失效问题，比如不要边遍历边删等
4. 除了常用的 begin 和 end 外，部分容器还提供了反向遍历迭代器

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| begin() | 首迭代器，代表第一个元素的位置 | O(1) |
| end() | 尾迭代器，代表最后一个元素的下一个位置 | O(1) |

```cpp
vector<int> v;
// ...

vector<int>::iterator iter = v.begin();
iter++;   // 移动迭代器
iter--;

for (auto it = v.begin(); it != v.end(); it++) {
    cout << *it << " ";
}

for (auto x : v) {             // 支持迭代器的容器可以使用 C++11 的扩展写法 foreach
    cout << x << " ";
}
```

> **注意 `end()` 的位置**：它指向**最后一个元素的下一个位置**，是“哨兵”，不能解引用（`*v.end()` 是未定义行为）。所以区间永远是**左闭右开** `[begin, end)`——这也是 STL 所有算法统一约定的区间形式。

### 1.3 list

链表，不支持随机访问。头文件：`#include <list>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| push_back() | 在最后插入一个元素 | O(1) |
| pop_back() | 在最后删除一个元素 | O(1) |
| push_front() | 在开头插入一个元素 | O(1) |
| pop_front() | 在开头删除一个元素 | O(1) |
| clear() | 清空 | O(n) |
| empty() | 判断是否为空 | O(1) |
| insert() | 插入 | O(1) |
| erase() | 删除 | O(1) |
| begin() | 首迭代器 | O(1) |
| end() | 尾迭代器 | O(1) |

#### 注意

1. **不要使用泛型的 sort**，list 有排序成员函数 `list.sort()`
2. 某些 Linux 下的 GCC 版本，对 `list.size()` 调用有性能问题，如果可以尽量避免使用，遍历链表建议使用迭代器

> **补充 · 为什么 list 不能用 std::sort**：`std::sort` 要求**随机访问迭代器**（要能 `it + n`、能算距离做快排的三数取中），而 `list` 只提供**双向迭代器**（只能 `++/--`）。所以标准库给了成员版 `list.sort()`——归并排序实现，只依赖双向迭代器，稳定，O(nlogn)，不占额外数组。
>
> 同理 `forward_list` 有 `sort()`，但不能用 `reverse` 之外需要双向移动的算法。
>
> **底层**：每个元素一个独立节点，节点里存 `prev/next` 两个指针 + 数据。所以「任意位置插删 O(1)」的前提是**你已经拿到了那个位置的迭代器**；如果只知道下标，还得先 O(n) 走过去。代价是每存一个元素要多付两个指针，且内存不连续、缓存不友好——这也是实践中 `vector` 常常比 `list` 快的原因。

### 1.4 string

C++ 的字符串，支持通过运算符进行连接、比较、拷贝。头文件：`#include <string>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| size() | 大小 | O(1) |
| [] | 随机访问 | O(1) |
| + | 字符串连接 | O(1) |
| substr() | 取子串 | O(n) |
| c_str() | 返回字符串的 char* 指针 | O(1) |

#### 注意

1. string 不支持 C 语言风格的字符串操作，如 strlen、strcmp 等，对 `c_str()` 也只有只读操作
2. 在使用 `+` 进行连接时，注意**加号两侧的参数应至少有一个为 string 类型**，不能写作 `"abc" + 1`
3. 某些版本的 GCC 不引用 string 头文件也可以使用，但是加上头文件才能使用 cin 和 cout 进行输入输出

> **补充**：
> - `"abc" + 1` 不是拼接，是**指针算术**，结果是 `const char*` 指向 `"bc"`。同理 `"a" + "b"` 是两个指针相加，直接编译错误。
> - `substr(pos, len)` 是 O(len) 不是 O(n)；`+` 的复杂度是 O(结果长度)，表里写 O(1) 是指单次追加的摊还开销，长串反复拼接请用 `append` 或先 `reserve`。
> - `c_str()` 返回的指针在 string 被修改或析构后失效，别长期持有。

### 1.5 stack

栈，后进先出，不支持随机访问。头文件：`#include <stack>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| size() | 大小 | O(1) |
| push() | 向栈顶插入元素 | O(1) |
| top() | 取栈顶元素 | O(1) |
| pop() | 弹出栈顶 | O(1) |
| empty() | 判断是否为空 | O(1) |

> **补充 · 两个高频坑**：
> 1. `pop()` **返回 void**，不返回被弹出的元素。要“取出并弹出”必须两步：`int x = s.top(); s.pop();`
> 2. `top()`/`pop()` 在空栈上调用是**未定义行为**（不是抛异常）。取值前先 `if (!s.empty())`。

### 1.6 queue

队列，先进先出，不支持随机访问。头文件：`#include <queue>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| size() | 大小 | O(1) |
| push() | 向队尾插入元素 | O(1) |
| front() | 取队首元素 | O(1) |
| pop() | 弹出队首元素 | O(1) |
| empty() | 判断是否为空 | O(1) |

> `pop()` 同样返回 void，且不返回元素。

### 1.7 priority_queue

优先队列，内部实现为堆，维护最值的容器。头文件：`#include <queue>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| size() | 大小 | O(1) |
| push() | 向堆插入元素 | O(logn) |
| top() | 取最大元素 | O(1) |
| pop() | 弹出堆顶元素 | O(logn) |
| empty() | 判断堆是否为空 | O(1) |

```cpp
priority_queue<int> heap1;                                 // 默认为大根堆
priority_queue<int, vector<int>, greater<int> > heap2;     // 小根堆，此时 top 为堆中最小值
// 1. 部分环境下，使用 greater<> 要 #include <functional>
```

> **补充**：三个模板参数依次是「元素类型 / 底层容器 / 比较器」。默认 `less<int>` 让**大的排前面**，所以 `top()` 是最大值；想要最小值就换成 `greater<int>`。自定义结构体要进堆，得提供 `operator<`（大根堆）或自己写比较器。

### 1.8 pair

二元组，将两个元素绑定到一起。比较大小时，先比较 first，first 相同才比较 second。头文件：`#include <utility>`

#### 基础操作

```cpp
pair<int, int> pii = make_pair(x, y);
cout << pii.first << " " << pii.second << "\n";
```

> **补充**：`pair` 的 `operator<` 是**字典序**比较，所以 `pair` 可以直接塞进 `set` 或直接 `sort`——这是「按 (x, y) 排序」最省事的写法。`map` 的 `value_type` 就是 `pair<const Key, T>`。

### 1.9 set / multiset

集合，会自动排序的容器，不支持随机访问，不支持重复元素，可以通过迭代器遍历。集合的概念参考离散数学（可以草率地理解为没有重复元素的容器，如果需要可重复元素的集合，可以使用 multiset，操作与 set 相近）。内部实现为红黑树。头文件：`#include <set>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| insert() | 插入元素 | O(logn) |
| erase() | 删除元素 | O(logn) |
| find() | 按值查找，返回目标迭代器/尾迭代器 | O(logn) |
| lower_bound() | 大于等于目标的第一个元素的迭代器 | O(logn) |
| upper_bound() | 大于目标的第一个元素的迭代器 | O(logn) |
| begin() | 首迭代器 | O(1) |
| end() | 尾迭代器 | O(1) |

#### 注意

1. **set 不要使用泛型的 lower_bound 和 upper_bound**，时间复杂度有问题
2. set 的移动迭代器 `++` 和 `--` 操作的时间复杂度为 O(logn)
3. 不要边插边删

> **补充 · 为什么泛型版本会慢**：`std::lower_bound` 是「二分」，它靠 `it + n` 跳位置——但 `set` 的迭代器只能 `++/--`，泛型算法只能退化成**线性前移**，O(n) 而不是 O(logn)。成员版 `s.lower_bound(x)` 直接在红黑树上二分，才是真 O(logn)。**凡是有同名成员版的算法，优先用成员版**（`set::find`、`map::find`、`list::sort`、`list::remove`…）。
>
> 红黑树是「近似平衡」的二叉搜索树，最坏树高仍是 O(logn)，所以增删查都稳定在 O(logn)。代价是每个节点额外存颜色和三个指针，内存开销明显大于 `vector`。

#### multiset

支持重复元素的 set，基本操作类似。

- `mst.count(x)` 返回 x 的个数
- erase 传入**迭代器**删除具体元素，传入**值**删除全部等值元素

### 1.10 map

映射，内部元素可以看成 pair，会自动排序的容器（按键排序），不支持随机访问，不支持重复键，可以通过迭代器遍历。使用时候，可以非常草率不负责任地理解为下标不再是数字的数组。内部实现为红黑树。头文件：`#include <map>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| [x] | 键为 x 的元素的值 | O(logn) |
| insert() | 插入 <键, 值> | O(logn) |
| erase() | 按键删除元素 | O(logn) |
| find() | 按键查找，返回目标迭代器/尾迭代器 | O(logn) |
| lower_bound() | 大于等于目标键的第一个元素的迭代器 | O(logn) |
| upper_bound() | 大于目标键的第一个元素的迭代器 | O(logn) |
| begin() | 首迭代器 | O(1) |
| end() | 尾迭代器 | O(1) |

#### 注意

1. 可以使用随机访问运算符进行插入，如 `mp[key] = value;`
2. 如果不存在 key，使用随机访问时会自动插入，默认值为 0
3. 可以通过迭代器遍历，移动迭代器同 set 为 O(logn) 复杂度

```cpp
// 避免自动插入，防止自动插入可以节约内存
if (mp.count(x))        // count 用于计数，map 不支持重复键所以只能为 0/1
{
    mp[x]
    // ...
}
```

> **补充 · `operator[]` 的隐形插入**是最常见的坑：
> - `if (mp["abc"])` 会在 key 不存在时**先插入** `{"abc", 0}`，再判断 0。查存在要用 `find()` 或 `count()`。
> - 也因为这个原因，`operator[]` **要求 value 类型可默认构造**；如果 value 是没有默认构造函数的类，只能用 `insert` / `emplace`。
> - 只想读不想插，用 C++11 的 `at()`（不存在抛 `out_of_range`）。
> - `mp[x]` 的复杂度是 O(logn)（要查树）+ 可能的插入；表里写 O(logn) 是对的，但它不只是“读”。

### 1.11 unordered_map

操作类似 map，但实现完全不同，内部为哈希，不支持自动排序。头文件：`#include <unordered_map>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| [x] | 键为 x 的元素的值 | O(1) |
| insert() | 插入 <键, 值> | O(1) |
| erase() | 按键删除元素 | O(1) |
| find() | 按键查找，返回目标迭代器/尾迭代器 | O(1) |
| begin() | 首迭代器 | O(1) |
| end() | 尾迭代器 | O(1) |

> **补充 · 底层是哈希表**：一串「桶」（bucket）数组，key 先过 `std::hash` 变成整数，再取模定位到桶。桶内冲突常见用**链地址法**（每个桶挂一条链/一棵小树）。
>
> - 装填因子 `load_factor() = size / bucket_count`，超过 `max_load_factor()`（默认 1.0）时触发 **rehash**：重建更大的桶数组、把所有元素重新分配位置。
> - **rehash 会让所有迭代器失效**（但指向元素的指针和引用仍然有效，因为节点本身没搬家）——这跟 `vector` 扩容“全失效”不同。
> - 自定义类型做 key，必须提供 `std::hash` 特化和 `operator==`。

### 1.12 unordered_set

操作类似 set，但实现完全不同，内部为哈希，不支持自动排序。头文件：`#include <unordered_set>`

#### 基础操作

| 操作 | 描述 | 复杂度 |
| --- | --- | --- |
| insert() | 插入元素 | O(1) |
| erase() | 删除元素 | O(1) |
| find() | 按值查找，返回目标迭代器/尾迭代器 | O(1) |
| begin() | 首迭代器 | O(1) |
| end() | 尾迭代器 | O(1) |

### 1.13 底层结构一览

这张表是「基础 → 底层」的分水岭，建议背下来：

| 容器 | 底层结构 | 迭代器类别 | 随机访问 | 内存布局 | 什么操作会让迭代器失效 |
| --- | --- | --- | --- | --- | --- |
| `array` | 内建数组 | 随机访问 | ✅ | 连续 | 不适用（不能增删） |
| `vector` | 连续动态数组 | 随机访问 | ✅ | 连续 | **扩容 → 全失效**；中间插删 → 插入点之后失效 |
| `deque` | 分段连续缓冲 + 中控数组 | 随机访问 | ✅ | 分段连续 | 中间插删 → 全失效；头尾插删只影响被删元素 |
| `list` | 双向链表 | 双向 | ❌ | 节点分散 | 只有被删节点失效 |
| `forward_list` | 单向链表 | 前向 | ❌ | 节点分散 | 只有被删节点失效 |
| `set` / `map` | 红黑树 | 双向 | ❌ | 节点分散 | 只有被删节点失效 |
| `unordered_*` | 哈希桶 | 前向 | ❌ | 桶 + 节点 | **rehash → 全失效**；删除只影响被删元素 |
| `stack` / `queue` / `priority_queue` | 适配器（默认 deque / deque / vector） | **无迭代器** | ❌ | 同底层容器 | — |

#### 一张图看完内存布局

[![STL 容器底层结构：连续 / 分段 / 节点 / 哈希桶](/images/stl-container-layout.svg)](/images/stl-container-layout.svg)

> 点图可在新标签页看原尺寸（正文栏比图窄，缩小后细节会糊）。

看这张图只抓三件事：

1. **盒子怎么排**——`array`/`vector` 是一个方框接一个方框（连续），`deque` 是几段方框各自连续（分段），`list`/`forward_list`/`set`/`map` 是散落的方框用箭头连起来（节点），`unordered_*` 是先落到桶里、再在桶内串成链。
2. **箭头代表什么**——相邻方框之间的箭头是**指针**，只能顺着跳，不能像数组那样「首地址 + 下标」一步算出。这就是为什么 `list` 有 `++` 却没有 `+n`。
3. **红黑树和哈希桶差在哪**——树是「有序」换来的 `O(log n)`：要找 `50` 得从根往下比两次；桶是「哈希」换来的平均 `O(1)`：`hash(key) % 桶数` 直接落到某一格，代价是**没有顺序**（遍历顺序 ≠ 大小顺序）。

> **一句话理解 deque**：它不是「一整块连续内存」，而是「若干块固定大小的连续缓冲区 + 一个中控指针数组」。所以头尾插入不用搬数据（O(1)），随机访问要两次间接（也不慢），但中间插入仍然要挪动大量元素（O(n)），而且内存不保证连续——**别把 `deque` 的元素地址传给需要连续内存的 C 接口**。

## 2. 迭代器与失效

### 2.1 五种迭代器类别

迭代器是**算法对容器的唯一要求**，算法的能力上限由迭代器类别决定：

| 类别 | 能力 | 典型容器 | 能用的算法 |
| --- | --- | --- | --- |
| 输入迭代器 Input | 单遍读、`++` | `istream_iterator` | `find`、`accumulate` |
| 输出迭代器 Output | 单遍写、`++` | `ostream_iterator`、`back_inserter` | `copy`、`fill` |
| 前向迭代器 Forward | 多遍读写、单向 | `forward_list`、`unordered_*` | 上一行 + `replace` |
| 双向迭代器 Bidirectional | 可 `++/--` | `list`、`set`、`map` | 上一行 + `reverse`、`list::sort` |
| 随机访问迭代器 Random Access | 可 `+n`、`-`、比较大小、下标 | `vector`、`deque`、`array`、原生指针 | **全部**，含 `sort`、`lower_bound` |

所以「`list` 不能用 `std::sort`」「`set` 不能用泛型 `lower_bound`」不是特例，是**迭代器类别不够**导致的必然结果。

### 2.2 失效规则（写代码时最容易出错的地方）

| 场景 | 后果 | 正确写法 |
| --- | --- | --- |
| 边遍历 `vector` 边 `erase` | 后面元素前移，迭代器错位/失效 | `for (auto it = v.begin(); it != v.end(); ) it = v.erase(it);` |
| `vector` 循环里 `push_back` | 可能扩容，`it` 全失效 | 先 `reserve`，或用下标循环 |
| `list` 里 `erase` 当前元素 | 只有当前失效 | 同上，用 `erase` 的返回值推进 |
| `map`/`set` 里 `erase` | 只有当前失效 | `it = mp.erase(it);`（C++11 起返回下一个迭代器） |
| `unordered_*` 插入触发 rehash | 迭代器全失效 | 别缓存迭代器；指针/引用仍可用 |
| 保存了 `end()` 再插入 | `end()` 可能变 | 每次重新取 `v.end()` |

## 3. 算法

> 头文件：`#include <algorithm>`（`sort`/`find`/`lower_bound`…）、`#include <numeric>`（`accumulate`/`iota`）。
> 所有算法都工作在**左闭右开区间** `[first, last)` 上，**不认识容器**，只认迭代器。

### 3.1 排序

#### sort

- 内部实现为快排（实际要复杂的多：内省排序 introsort = 快排 + 堆排 + 插入排序的混合）
- 前两个参数代表排序的区间（迭代器或地址）
- 默认为升序排序，可以传入第三个参数指定排序规则
- 时间复杂度为 O(nlogn)
- 注意：结构体数组排序可以传入第三个参数指定，也可以重载运算符 `<`

```cpp
int a[N];
vector<int> v;
// ...

sort(a, a + n);                              // 数组
sort(v.begin(), v.end());                    // vector
sort(v.begin(), v.end(), greater<int>());    // 降序（greater 让大数在前）

bool cmp(int a, int b) {
    return a > b;                            // 此处为 > 则为降序，< 为升序
}

sort(v.begin(), v.end(), cmp);
```

> **补充 · 比较函数必须是「严格弱序」**：`cmp(a, b)` 表示「a 是否应该排在 b 前面」，相等时必须返回 `false`（写 `a <= b` 会在某些数据上直接崩溃/越界——这是 `sort` 最常见的运行时崩溃原因）。要稳定排序用 `stable_sort`。

### 3.2 二分

**要在有序的情况下才能使用。**

#### 1. binary_search

- 二分查找，找到返回 true
- 前两个参数代表排序的区间（迭代器或地址）
- 第三个参数为要查找的值
- 如果不是升序数组，需要指定第四个参数（排序规则），同第三参数
- 时间复杂度 O(logn)

#### 2. lower_bound

- 二分查找**大于等于**目标元素的第一个元素的迭代器（不存在则返回尾迭代器）
- 基本参数同上
- 时间复杂度 O(logn)

#### 3. upper_bound

- 二分查找**大于**目标元素的第一个元素的迭代器（不存在则返回尾迭代器）
- 基本参数同上
- 时间复杂度 O(logn)

#### 4. equal_range

- 二分查找等于目标元素的**范围**，返回一对迭代器（pair），表示要找区间（左闭右开）的迭代器
- 基本参数同上
- 时间复杂度 O(logn)

```cpp
sort(a, a + n); binary_search(a, a + n, x);

sort(a, a + n, greater<int>()); binary_search(a, a + n, x, greater<int>());

sort(a, a + n, cmp); binary_search(a, a + n, x, cmp);

sort(a, a + n); lower_bound(a, a + n, x);

// 如果是 vector 或数组，可以减去首迭代器获取对应元素的索引
id = lower_bound(a, a + n, x) - a;
id = lower_bound(v.begin(), v.end(), x) - v.begin();
```

> **补充 · 三者的关系**：
> - `lower_bound` = 第一个 `>= x` 的位置；`upper_bound` = 第一个 `> x` 的位置。
> - 两者相减 = **x 出现的次数**（这就是 `equal_range` 的返回对）。配合 `sort` 可以替代 `multiset` 做离线统计。
> - 区间必须**已按同一个比较规则有序**，否则结果无意义（不会报错，只是答案错）。
> - 找不到时返回的是 `last`（尾迭代器），所以取下标后要判断 `id != n`。

### 3.3 其他泛型算法

#### 1. reverse

反转数组，O(n)。

```cpp
reverse(a, a + n);
reverse(v.begin(), v.end());
```

#### 2. fill

给容器填充为某个值；`fill_n`：填充前 n 个元素。

```cpp
// for 循环
for (int i = 0; i < n; i++) {
    a[i] = 0;
}

// fill
fill(a, a + n, 0);
fill(v.begin(), v.end(), 0);

fill_n(a, n, 0);
fill_n(v.begin(), n, 0);

// 数组如果填充 0 或 -1，也可以使用 C 语言的函数 memset，
// 头文件 cstring 或 cstdlib
// 不要乱用！不要乱用！不要乱用！尤其是填充其他值，除非你知道函数内部做了什么
memset(a, 0, n * sizeof(int));
```

> **补充 · 为什么 memset 只能填 0 / -1**：`memset` 是**按字节**赋值。`0` 的四个字节都是 `0x00`，`-1` 的四个字节都是 `0xFF`，所以对 `int` 恰好得到 0 和 -1。填 `1` 会得到 `0x01010101 = 16843009`，填 `0.5` 更是无意义。填充其他值用 `fill`，或者 `std::fill` 的批量版。

#### 3. copy

将第一个容器的元素拷贝给第二个容器，**注意第二个容器要有足够的空间**。

```cpp
vector<int> target(origin.size());
copy(origin.begin(), origin.end(), target.begin());
```

> **补充**：目标容器空间不够就直接写越界（未定义行为）。想“边拷边扩容”用插入迭代器：`copy(src.begin(), src.end(), back_inserter(dst));`（需 `#include <iterator>`）。

#### 4. 最值

`max(a, b)` 返回 a 和 b 的最大值，`min` 返回最小值。

```cpp
max(a, b);
max(a, max(b, c));

int mx = -1;
for (int i = 0; i < n; i++) {
    mx = max(mx, a[i]);
}
```

> 整段求最值也可以直接 `*max_element(v.begin(), v.end())` / `*min_element(...)`（`<algorithm>`）。

#### 5. 杂

1. `to_string()`：传入数值类型，返回 string
2. `unique()`：针对有序数组，将重复元素移动到末尾，返回移动后第一个重复位置的迭代器，配合 erase 和 sort 可以实现去重
3. `__gcd()`：最大公约数，时间复杂度为 O(logn)
4. `next_permutation()`：生成下一个排列，时间复杂度 O(n)，但是因为排列数很多，所以很少用

```cpp
// unique + erase 去重（必须先排序）
sort(v.begin(), v.end());
v.erase(unique(v.begin(), v.end()), v.end());
```

> **注意 `unique` 只“挪”不“删”**：它把不重复的元素往前 compaction，返回新的逻辑尾，真正的删除得靠 `erase`。另外 `__gcd` 是 GCC 扩展（两个下划线开头是编译器保留名），标准写法是 `std::gcd`（C++17，`<numeric>`）。

## 4. 模板、重载与内存

这一节是你笔记里只列了词条、没展开的部分，我按「学 STL 必须懂的那一层」补上。

### 4.1 模板：泛化的地基

STL 全部建立在模板上——容器是**类模板**，算法是**函数模板**。编译器在你写下 `vector<int>`、`sort(v.begin(), v.end())` 时，按需**实例化**出具体代码。

```cpp
template <typename T>          // 函数模板
T myMax(T a, T b) { return a > b ? a : b; }

template <typename T>          // 类模板
class Box { T data; };
```

### 4.2 泛化、全特化、偏特化

| 概念 | 英文 | 含义 | 例子 |
| --- | --- | --- | --- |
| 泛化（主模板） | primary template | 最通用的版本 | `template<class T> struct hash;` |
| 全特化 | full specialization | 为某个**具体类型**单独实现 | `template<> struct hash<bool> { ... };` |
| 偏特化 | partial specialization | 为**一类类型**单独实现（指针、引用、`vector<T>`…） | `template<class T> struct hash<T*> { ... };` |

```cpp
template <class T> struct TypeName { static const char* get() { return "general"; } };  // 泛化
template <>        struct TypeName<int> { static const char* get() { return "int"; } }; // 全特化
template <class T> struct TypeName<T*>  { static const char* get() { return "pointer"; } }; // 偏特化
```

要点（补充）：

- **偏特化只能用于类模板**；函数模板只能全特化，或者干脆用**重载**代替（实践中都选重载）。
- 特化的目的是「对某些类型换一套更高效或更正确的实现」——`std::hash` 对整型直接用值、对字符串要算哈希，就是全特化/偏特化的经典用法。你自定义类型要当 `unordered_map` 的 key，写的正是 `std::hash<MyType>` 的全特化。
- 模板的代价：**编译期展开**，代码膨胀、报错信息极长；但运行时零开销（没有虚函数、没有装箱）。

### 4.3 操作符重载：让自定义类型“像内置类型”

STL 到处依赖操作符，所以重载它们等于给你的类型发“通行证”：

| 重载 | 作用 | STL 里的用处 |
| --- | --- | --- |
| `operator<` | 定义“小于” | 结构体直接放进 `set`/`map`、直接 `sort` |
| `operator==` | 定义“相等” | `find`、`unordered_*` 的桶内比较 |
| `operator()` | 让对象能像函数一样调用 | 写**仿函式**（`less`、自定义比较器） |
| `operator[]` | 下标访问 | `map`、自定义容器 |
| `operator*` / `++` | 解引用 / 前进 | 自定义**迭代器**必须实现 |

仿函式的最小例子：

```cpp
struct CmpByAbs {                       // 仿函式：重载 operator()
    bool operator()(int a, int b) const { return abs(a) < abs(b); }
};
sort(v.begin(), v.end(), CmpByAbs());
```

### 4.4 operator new 与 malloc

| 对比项 | `new` / `delete` | `malloc` / `free` |
| --- | --- | --- |
| 本质 | **运算符**（可重载） | **库函数** |
| 是否调用构造/析构 | ✅ 分配后调构造函数，`delete` 先调析构 | ❌ 只给一块裸内存 |
| 大小 | 编译器自动算 | 要自己 `sizeof` |
| 返回类型 | 类型化指针 `T*` | `void*`，需强转 |
| 失败行为 | 抛 `std::bad_alloc`（或 `nothrow` 版返回 nullptr） | 返回 `NULL` |
| 释放配对 | `new` ↔ `delete`，`new[]` ↔ `delete[]`（**不能混**） | `malloc` ↔ `free`（**不能混**） |
| 底层关系 | `operator new` 内部通常就是调 `malloc` | — |

```cpp
int* p1 = new int(5);          // 分配 + 初始化为 5
int* p2 = new int[10];         // 10 个 int，未初始化
delete p1;
delete[] p2;                   // 数组必须用 delete[]

int* p3 = (int*)malloc(10 * sizeof(int));
free(p3);
```

> **placement new**（补充）：`new (ptr) T(...)` 在**已分配好的内存**上构造对象，不申请空间——`vector` 扩容时搬元素、`allocator` 的实现都靠它把「分配内存」和「构造对象」这两步拆开。这正是「分配器」这个部件存在的意义。
